### 历史回滚方案概述

#### 1.1 核心思路

**不动现有目录结构，只在 csv2x-workspace 外层加一个软链接实现整体切换。**

```plain
/root/csv2x/
├── csv2x-workspace ──→ csv2x-workspace-v1    ← 唯一的软链接，掰到哪就跑哪
├── csv2x-workspace-v1/                        ← 当前运行版本（全部文件保留）
│   ├── factory/factory/
│   ├── platform/platform/
│   ├── v2x/          (bin/start.sh stop.sh + v2x-server.jar)
│   ├── scsc/          (bin/start.sh stop.sh + manage-start.jar)
│   └── nginx/
├── csv2x-workspace-v2/                        ← 新版本（部署到这里）
├── start.sh  stop.sh  start_v2x.sh  start_scsc.sh  ...
└── ...
```

#### 1.2 工作原理

软链接本质是一个"指针"——操作系统读到 `csv2x-workspace` 时自动替换为它指向的真实目录。

```plain
脚本里写的路径：     csv2x-workspace/factory/factory/bin/restart.sh
                              │
                   操作系统自动解析软链接
                              │
                              ▼
实际访问的目录：   csv2x-workspace-v1/factory/factory/bin/restart.sh
```

切换软链接就是改一行指向，不复制不移动任何文件：

```bash
ln -sfn csv2x-workspace-v2 csv2x-workspace
```

#### 1.3 涉及模块

| 模块                 | 端口 | 启停方式                             | 打包产物                        | 服务器部署方式                               |
| -------------------- | ---- | ------------------------------------ | ------------------------------- | -------------------------------------------- |
| factory（厂商服务）  | 8889 | `./bin/restart.sh` / `./bin/stop.sh` | `factory-assembly.tar.gz`       | 解压到 `csv2x-workspace/factory/`            |
| platform（平台服务） | 8888 | `./bin/restart.sh` / `./bin/stop.sh` | `platform-assembly.tar.gz`      | 解压到 `csv2x-workspace/platform/`           |
| v2x（OEM 城市服务）  | 9102 | `./bin/start.sh` / `./bin/stop.sh`   | `v2x-server-1.0.0-SNAPSHOT.jar` | 替换 `csv2x-workspace/v2x/v2x-server.jar`    |
| scsc（数据开放服务） | 3210 | `./bin/start.sh` / `./bin/stop.sh`   | `manage-start-1.0-SNAPSHOT.jar` | 替换 `csv2x-workspace/scsc/manage-start.jar` |

#### 1.4 启停脚本层次

四个模块遵循统一的启停约定——顶层脚本负责调度，底层脚本负责干活：

```plain
/root/csv2x/
├── start.sh         → 调用 factory/bin/restart.sh + platform/bin/restart.sh
├── stop.sh          → 调用 factory/bin/stop.sh + platform/bin/stop.sh
├── start_v2x.sh     → cd v2x && ./bin/start.sh
├── start_scsc.sh    → cd scsc && ./bin/start.sh
│
└── csv2x-workspace/（软链接，切换版本不影响顶层脚本）
    ├── factory/factory/bin/   → restart.sh  stop.sh  app_check.sh
    ├── platform/platform/bin/ → restart.sh  stop.sh  app_check.sh
    ├── v2x/bin/              → start.sh  stop.sh
    └── scsc/bin/             → start.sh  stop.sh
```

:::tips
关于是否通过脚本来进行项目的统一启停,这个可以各自选择.这里都有提供

:::

**接入我们新的 scsc 模块**

1. 创建 scsc 目录结构

```bash
mkdir -p /root/csv2x/csv2x-workspace/scsc/bin
```

2. 创建 scsc 底层启停脚本

`csv2x-workspace/scsc/bin/start.sh`**：**

```bash
cat > /root/csv2x/csv2x-workspace/scsc/bin/start.sh << 'EOF'
#!/usr/bin/env bash
set -u
set -e

BIN=$(cd `dirname $0`; pwd)
SCSC_DIR="$(cd "${BIN}/.."; pwd)"

cd $SCSC_DIR

echo "starting scsc (manage-start) ..."
nohup java -jar manage-start.jar > /dev/null 2>&1 &
echo "scsc started (PID: $!)"

echo "done."
EOF

chmod +x /root/csv2x/csv2x-workspace/scsc/bin/start.sh
```

`csv2x-workspace/scsc/bin/stop.sh`**：**

```bash
cat > /root/csv2x/csv2x-workspace/scsc/bin/stop.sh << 'EOF'
#!/usr/bin/env bash
set -u
set -e

APP_JAR="manage-start.jar"

PID=$(pgrep -f "$APP_JAR")
if [ -z "$PID" ]; then
  echo "$APP_JAR not running"
  exit 0
fi

echo "stopping $APP_JAR (PID: $PID) ..."
kill $PID

TIMEOUT=5
while [ $TIMEOUT -gt 0 ]; do
  if ! pgrep -f "$APP_JAR" > /dev/null; then
    echo "stopped"
    exit 0
  fi
  sleep 1
  TIMEOUT=$((TIMEOUT - 1))
done

echo "force stop ..."
kill -9 $PID
sleep 1

if pgrep -f "$APP_JAR" > /dev/null; then
  echo "Error: stop failed"
  exit 1
else
  echo "stopped"
  exit 0
fi
EOF

chmod +x /root/csv2x/csv2x-workspace/scsc/bin/stop.sh
```

:::tips
模仿 v2x 的启停脚本的逻辑

:::

3. 创建 scsc 顶层调度脚本

在 `/root/csv2x/` 下创建 `start_scsc.sh`（仿照 `start_v2x.sh`），只负责调度，实际启停由底层脚本完成：

```bash
cat > /root/csv2x/start_scsc.sh << 'EOF'
#!/usr/bin/env bash
set -u
set -e

DEPLOY_PATH=/root/csv2x/csv2x-workspace

cd $DEPLOY_PATH/scsc
./bin/start.sh

echo "done."
EOF

chmod +x /root/csv2x/start_scsc.sh
```
