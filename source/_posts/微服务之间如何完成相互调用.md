# 微服务之间如何完成互调用

## 概述

在我们所有的微服务项目之间,要完成,服务于服务之间的互相调用.主要有两种技术,一个是Feign还有一个是阿里的Dubbo.但是他们的实现逻辑差不多

## 完整链路

我们用Fegin为样例,来讲解下这个链路

#### 第一步

我们会先在相关Service-Api中定义我们的远程接口契约,

```java
// 📍 Feign 接口：定义远程调用契约
@FeignClient(
    value = AppConstant.APPLICATION_SYSTEM_NAME,  // 目标服务名
    fallback = IDictClientFallback.class          // 降级类
)
public interface IDictClient {

    @GetMapping("/dict/getValue")
    R<String> getValue(@RequestParam("code") String code,
                       @RequestParam("dictKey") Integer dictKey);
    // ← 没有实现！只有方法签名 + HTTP 映射
}
```

他这个接口的作用就是我要将我这个服务当中那些服务我们暴露出来,给其他的微服务进行调用.

#### 第二步

我们将我们需要的那个服务,通过接口暴露出来,那我们的具体实现还是在我们相关的Serveice项目当中实现这个接口

```java
// 📍 远程接口的服务端实现
@ApiIgnore
@RestController  // ← 标记为 REST Controller，对外暴露 HTTP 接口
public class DictClient implements IDictClient {

    @Resource
    private IDictService service;  // ← 注入本地 Service！

    @Override
    @GetMapping("/dict/getValue")  // ← 路径必须与 IDictClient 一致
    public R<String> getValue(String code, Integer dictKey) {
        // 先转调本地 Service，执行业务逻辑
        return R.data(service.getValue(code, dictKey));
    }
}
```

在这段代码当中,我们注入我们IDictService的这个Bean 是我们的本地的.其实真正在实现的是我们本地服务写的业务操作.这个简单的接口实现,主要是用来包裹的,你可以把它当我们本地服务当中的controller层.

#### 第三步

这个就是我们的具体操作的业务代码

```java
@Service
public class DictServiceImpl extends ServiceImpl<DictMapper, Dict>
    implements IDictService {

    @Override
    @Cacheable(cacheNames = DICT_VALUE, key = "#code+'_'+#dictKey")
    public String getValue(String code, Integer dictKey) {
        return Func.toStr(baseMapper.getValue(code, dictKey), StringPool.EMPTY);
        // 执行真正的 DB 查询
    }
}
```

#### 第四步

消费方,现在我们要进行消费,我们必须通过Maven依赖blade-dict-api,直接注入IDictClint

```java
// 在 blade-desk 服务中
@Resource
private IDictClient dictClient;  // ← Feign 代理对象

public void someMethod() {
    // 这行代码背后，Spring Cloud 会：
    // 1. 从 Nacos 找到 blade-system 的实例 IP
    // 2. 通过 HTTP 发送 GET 请求
    // 3. 接收响应并反序列化
    R<String> result = dictClient.getValue("menu_category", 1);
    // ↑ 看似本地调用，实际是远程 HTTP 请求！
}
```

## 三层调用链全景

```
前端 HTTP 请求
    │
    ▼
┌─────────────────────────────────────────┐
│  Controller 层 (blinkerController)       │
│  调用本地 Service                        │
│  blinkerService.getSharedLampInfo()     │◄── 本地方法调用
└──────────────────┬──────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│  Service 层 (业务接口+实现)               │
│  IDictService ← DictServiceImpl         │
│  处理核心业务逻辑 + 缓存 + 事务            │◄── 本地方法调用
└──────────────────┬──────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│  Mapper 层 (MyBatis-Plus)                │
│  DictMapper → MySQL / Redis              │◄── 数据访问
└─────────────────────────────────────────┘


但当跨服务调用时，中间插入了 Feign 层：

┌─────────────────────────────────────────┐
│  消费方 Controller/Service              │
│  dictClient.getValue()                  │◄── 看似本地调用
└──────────────────┬──────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│  Feign 代理层 (IDictClient 接口)         │
│  Spring Cloud 自动生成代理对象            │
│  构造 HTTP 请求 → 发送网络请求            │◄── 远程调用！
└──────────────────┬──────────────────────┘
                   │
                   ▼ (网络传输)
┌─────────────────────────────────────────┐
│  提供方 Feign 实现 (DictClient)           │
│  @RestController + implements IDictClient│
│  接收 HTTP 请求 → 转调本地 Service        │
└──────────────────┬──────────────────────┘
                   │
                   ▼
              本地 Service 层
              (同上)
```
